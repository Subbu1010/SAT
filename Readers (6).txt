
Medical Equipment Reservations

Question

We are building a program to manage shared medical equipment bookings for a clinic. The clinic has multiple pieces of equipment, such as imaging rooms and portable devices, and staff can reserve them for specific time periods.

Definitions:

An equipment is an object representing a reservable item. It has properties for the ID and name.
A reservation is an object representing a staff booking for a specific piece of equipment over a time period. Times are represented as integers in minutes from the start of the day.
A RentalManager is the class used to manage all equipment and reservations.

To begin with, we present you with two tasks:

1-1) Read through and understand the code below. Please take as much time as necessary, and feel free to run the code.
1-2) One of the tests is failing due to a bug in the code. Make the necessary changes to RentalManager to fix the bug.


Support Reservation Status Reporting

Question

We are updating our system to support reservation status reporting. Clinic coordinators need to quickly see which reservations are still active, and they also need to understand how much booked time is currently active versus cancelled.

Add the following functions to RentalManager:

2-1) get_active_reservation_ids()
This function takes no arguments and returns a sorted list of reservation IDs for all ACTIVE reservations. If there are no active reservations, return an empty list.

2-2) get_total_minutes_by_status()
This function takes no arguments and returns a map with two keys:
"ACTIVE": the total duration in minutes across all active reservations.
"CANCELLED": the total duration in minutes across all cancelled reservations.
Both keys must always be present, even if the total is 0.

To assist you in testing these new functions, we have provided the test_get_active_reservation_ids and test_get_total_minutes_by_status functions.


Finding a Backup Device

Question

When clinical staff request a specific piece of equipment but it is not available, coordinators want the system to immediately suggest the best compatible alternative instead of manually checking the equipment list.

Add the following function to RentalManager:

3) find_best_equipment()
This function takes a preferred equipment ID and a requested start and end time.
If the preferred equipment is available for the requested period, return its ID.
If it is not available, consider only other equipment that shares the same equipment_type as the preferred equipment. Among the compatible equipment that is available for the requested period, return the one with the lowest total number of minutes across its own active reservations. If two or more compatible options are tied on total minutes, return the one with the lowest equipment ID.
If no compatible equipment is available for the requested period, return the language-appropriate absent value.

To assist you in testing this new function, we have provided the test_find_best_equipment function.


Planning for an Equipment Outage

Question

When a piece of equipment unexpectedly goes out of service, coordinators need an immediate plan for where its already-scheduled reservations should move, instead of reassigning each one by hand.

Add the following function to RentalManager:

4) get_reassignment_plan()
This function takes the ID of a piece of equipment going out of service and returns an object or structure containing:

reassignments: a map from each affected reservation's ID to the ID of the equipment it should move to.
unresolved: a list of the IDs of any affected reservations that could not be moved anywhere.

Affected reservations are the active reservations currently on the failing equipment, processed one at a time in ascending order of start_time, with ties broken by ascending reservation ID.

For each reservation:

Consider only other equipment with the same equipment_type.
The equipment must have no scheduling conflict with any existing reservation on it, including reservations already assigned to it earlier in this reassignment plan.
Among the remaining candidates, choose the equipment currently carrying the fewest active reservations. Break ties by the lowest equipment ID.
If no suitable equipment exists, add the reservation ID to unresolved.
This function only computes a reassignment plan. It must not modify any reservation's stored status or assigned equipment.

Example:

Equipment 5 goes out of service holding R201 (480-540) and R202 (600-660).
Equipment 6 and 7 are compatible substitutes. Equipment 6 already has one active reservation elsewhere in the day, while equipment 7 has none.
The resulting plan reassigns R201 to equipment 7 and R202 to equipment 6.

If the equipment going out of service has no active reservations, return empty collections for both parts of the result.

To assist you in testing this new function, we have provided the test_get_reassignment_plan function.

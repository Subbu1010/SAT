
Music Streaming Library

Question

We are building the analytics back-end for a music streaming platform. The system tracks a song catalog and a stream of play events. For each play event we record:

which user listened
which song they played
how long they listened (in seconds)
whether they completed the song or skipped before it ended

A play is considered "completed" when listened_seconds is at least the song's duration. A play is considered "skipped" when listened_seconds is less than the song's duration.

Definitions:

A "song" has: song_id, title, artist, duration_seconds.
A "play event" has: play_id, user_id, song_id, listened_seconds.
MusicLibrary manages the catalog and play events and provides listener statistics.

To begin with, we present you with two tasks:

1-1) Read through and understand the code below. Feel free to run it.
1-2) The test for MusicLibrary is not passing due to a bug in the code. Make the necessary changes to MusicLibrary to fix the bug.


Catalog Search and Deduplication

Question

Now that the library can track listener statistics, staff need tools to search the catalog and identify duplicate song entries.

2-1) get_songs_by_artist(): Takes an artist name and returns a list of song IDs whose artist matches the given name, case-insensitively, sorted by song_id ascending. Returns an empty list if no songs match.

2-2) find_duplicate_groups(): Two songs are duplicates if they have the same title (case-insensitive), the same artist (case-insensitive), and the same duration_seconds. All song IDs are unique. For each group of duplicates, keep the song with the smallest song_id. Return a list of (kept_song_id, merged_ids) entries where merged_ids is a sorted list of the remaining song IDs, sorted by kept_song_id ascending. Only include groups with at least two songs.

To assist you in testing the new functions, we have provided the test_get_songs_by_artist and test_find_duplicate_groups tests.


Artist Engagement Scoring

Question

The team wants to measure how well each artist is engaging listeners. For each artist, the engagement score considers how many plays were completed and how many distinct users listened, but penalizes artists whose songs are frequently skipped.

To implement these changes, we need to add a new function to the MusicLibrary class:

3) get_artist_engagement(min_plays, skip_penalty_threshold): For each artist with songs in the catalog, computes total_plays, completed_plays, unique_listeners, and skip_rate. If skip_rate is strictly greater than skip_penalty_threshold, engagement_score = completed_plays; otherwise engagement_score = completed_plays * unique_listeners. Only includes artists whose total_plays meets or exceeds min_plays. Returns a list of (artist_name, engagement_score) sorted by engagement_score descending, then artist_name ascending.

To assist you in testing the new function, we have provided the test_get_artist_engagement test.


Song Recommendations

Question

We want to recommend songs to a user based on what similar listeners have completed. Two users are "similar" if they have both completed at least one of the same songs.

To implement these changes, we need to add a new function to the MusicLibrary class:

4) get_song_recommendations(user_id, count): Builds the given user's completed-song profile, then for every other user who shares at least one completed song computes an overlap count. Each candidate song (completed by an overlapping user, but not by the given user) gets a score equal to the sum of overlap counts from all overlapping users who completed it. Returns a list of (song_id, score) sorted by score descending, then song_id ascending, capped at count entries. Returns an empty list for an unknown user, a user with no completed songs, or a non-positive count.

To assist you in testing the new function, we have provided the test_get_song_recommendations_case1 and test_get_song_recommendations_case2 tests.

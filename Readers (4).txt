
Claim Statistics Bug

Question

We are building a program to manage an insurance company's claims. The system tracks multiple claims, each with a unique ID, policyholder, claim type, amount, and current status. The program allows claims staff to add new claims, update claim statuses, and get statistics about resolved claims.

Definitions:

A "claim" is an object that represents an insurance claim. It has properties for the ID, policyholder ID, claim type, amount, and current status.
A "claims system" is a class which is used for managing all claims for the insurance company.

To begin with, we present you with two tasks:

1-1) Read through and understand the code below. Please take as much time as necessary, and feel free to run the code.
1-2) The test for ClaimsSystem is not passing due to a bug in the code. Make the necessary changes to ClaimsSystem to fix the bug.


Track Status Changes

Question

Insurance claims move through multiple status changes over their lifecycle. To support operational reporting, we record a history of every status change on each claim (what changed, who changed it, when), and then aggregate activity across the whole system.

Definitions (in addition to those from Q1):

A "status change" is a record of a single change to a claim's status. It captures the new status, the role of the approver making the change, and the timestamp of the change (integer hours since a reference point).

To implement this:

2-1) Extend the Claim class so each claim has an attribute named status_history (a list of StatusChange records).

2-2) Implement record_status_change(claim_id, new_status, approver_role, timestamp) on ClaimsSystem. This method should update the claim's current status and append a new StatusChange record to the claim's status history.

2-3) Implement get_status_change_counts_per_role() on ClaimsSystem. This method returns a mapping from each approver_role to the total number of status changes made by that role, aggregated across all claims. Roles that have not made any changes should not appear in the output.

Please discuss your approach for both functions before implementing them.


Approval Tier Routing

Question

The insurance company routes each claim to an approver of the appropriate tier based on business policy. Not every claim can be approved by anyone - larger amounts, more sensitive claim types, and previously-rejected claims all require more senior approvers.

3-1) Implement get_approver_tier() on ClaimsSystem. Given a claim, this method returns the required approver tier as one of these string values: "JUNIOR", "SENIOR", or "MANAGER" (matching the approver_role string convention introduced in Q2). Do not define a new enum for tiers, return the strings directly.

The rules are:

Amount-based tiering (base):
If amount < $1,000, the required tier is JUNIOR.
If $1,000 <= amount < $10,000, the required tier is SENIOR.
If amount >= $10,000, the required tier is MANAGER.

Type-based floor:
Any HEALTH claim requires at least SENIOR, regardless of amount.

Resubmission floor:
Any claim whose status history contains a prior REJECTED entry requires at least MANAGER, regardless of amount or type.

"At least" means the floor rules can only raise the required tier, never lower it. A $50,000 HEALTH claim is still MANAGER. A $500 AUTO claim that was previously REJECTED is MANAGER.

Please discuss your approach before implementing.


Role Co-occurrence

Question

The insurance operations team wants to understand parallel workload in the approval pipeline. When two different approver roles hold claims during overlapping time windows, that represents concurrent work, even on different claims. Roles that frequently co-hold claims indicate parallel processing capacity. Roles that rarely overlap suggest a serial handoff pattern where one role waits on the other.

Definitions:

A role "holds" a claim during the time between a status change assigning that role to the claim and the next status change (regardless of which role made the next change). If the same role appears in a claim's history multiple times, each hold is a separate interval.

Two roles "co-occur" when they simultaneously hold claims (potentially different claims) during overlapping time windows.

The final entry in a claim's status history does not represent a holding interval, since the role's hold has no recorded end.

4-1) Implement get_role_cooccurrence() on ClaimsSystem. This method returns a list of (role_1, role_2, total_overlap_hours) tuples describing role pairs with positive total co-occurrence across all claims.

For each tuple:

role_1 and role_2 are strings, with role_1 < role_2 alphabetically.
total_overlap_hours is an integer.
Only include pairs with total_overlap_hours greater than 0.

Sort the list by total_overlap_hours descending. Break ties by role_1 ascending, then by role_2 ascending.

Return an empty list if no pairs have positive co-occurrence.

Please discuss your approach before implementing.



/*
We are building a program to manage an insurance company's claims.
The system tracks multiple claims, each with a unique ID, policyholder,
claim type, amount, and current status. The program allows claims staff
to add new claims, update claim statuses, and get statistics about
resolved claims.

Definitions:
* A "claim" is an object that represents an insurance claim.
  It has properties for the ID, policyholder ID, claim type,
  amount, and current status.
* A "ClaimsSystem" is a class which is used for managing all
  claims for the insurance company.

To begin with, we present you with two tasks:
1-1) Read through and understand the code below. Feel free to run it.
1-2) The test for ClaimsSystem is not passing due to a bug in the code.
     Make the necessary changes to ClaimsSystem to fix the bug.
*/

import java.util.ArrayList;
import java.util.HashMap;
import java.util.Map;
import java.util.Objects;
import org.junit.Test;
import org.junit.runner.JUnitCore;
import org.junit.runner.Result;
import org.junit.runner.notification.Failure;
import static org.junit.Assert.*;

public class Solution {

    /**
     * Claim Status is of four types: SUBMITTED, UNDER_REVIEW,
     * APPROVED, and REJECTED.
     * SUBMITTED and UNDER_REVIEW are active states for claims
     * still being processed.
     * APPROVED and REJECTED are terminal (resolved) states.
     */
    enum ClaimStatus {
        SUBMITTED, UNDER_REVIEW, APPROVED, REJECTED
    }

    /**
     * Claim Type indicates the category of the insurance claim:
     * AUTO, HEALTH, and PROPERTY.
     */
    enum ClaimType {
        AUTO, HEALTH, PROPERTY
    }

    /** Data about an insurance claim. */
    static class Claim {
        final int claimId;
        final int policyholderId;
        final ClaimType claimType;
        final double amount;
        ClaimStatus status;

        Claim(int claimId, int policyholderId,
              ClaimType claimType, double amount,
              ClaimStatus status) {
            this.claimId = claimId;
            this.policyholderId = policyholderId;
            this.claimType = claimType;
            this.amount = amount;
            this.status = status;
        }

        @Override
        public boolean equals(Object other) {
            if (!(other instanceof Claim c)) {
                return false;
            }
            return claimId == c.claimId
                    && policyholderId == c.policyholderId
                    && claimType == c.claimType
                    && Double.compare(amount, c.amount) == 0
                    && status == c.status;
        }

        @Override
        public int hashCode() {
            return Objects.hash(claimId, policyholderId,
                    claimType, amount, status);
        }

        @Override
        public String toString() {
            return "Claim ID: " + claimId
                    + ", Policyholder: " + policyholderId
                    + ", Type: " + claimType + ", Amount: " + amount
                    + ", Status: " + status;
        }
    }

    /**
     * Data for managing insurance claims, and methods which staff can
     * use to perform any queries or updates.
     */
    static class ClaimsSystem {
        final ArrayList<Claim> claims = new ArrayList<>();

        /** Adds a claim to the system. */
        void addClaim(Claim claim) {
            claims.add(claim);
        }

        /** Update the status of the given claim. */
        void updateClaimStatus(int claimId, ClaimStatus status) {
            for (Claim claim : claims) {
                if (claim.claimId == claimId) {
                    claim.status = status;
                    break;
                }
            }
        }

        /** Calculates and returns statistics for all claims. */
        Map<String, Object> getClaimStatistics() {
            int totalClaims = claims.size();
            int totalResolvedClaims = 0;
            for (Claim claim : claims) {
                if (claim.status == ClaimStatus.APPROVED) {
                    totalResolvedClaims++;
                }
            }
            double resolutionRate =
                    ((double) totalResolvedClaims / totalClaims) * 100;
            Map<String, Object> result = new HashMap<>();
            result.put("total_claims", totalClaims);
            result.put("total_resolved_claims", totalResolvedClaims);
            result.put("resolution_rate", resolutionRate);
            return result;
        }
    }

    /**
     * This is not a complete test suite, but tests some basic
     * functionality of the code and shows how to use it.
     */
    public static class TestSuite {

        @Test
        public void testClaim() {
            Claim c = new Claim(1, 101, ClaimType.AUTO,
                    2500.00, ClaimStatus.SUBMITTED);
            assertEquals(1, c.claimId);
            assertEquals(101, c.policyholderId);
            assertEquals(ClaimType.AUTO, c.claimType);
            assertEquals(2500.00, c.amount, 0.001);
            assertEquals(ClaimStatus.SUBMITTED, c.status);
        }

        @Test
        public void testClaimsSystem() {
            ClaimsSystem system = new ClaimsSystem();

            Claim c1 = new Claim(1, 101, ClaimType.AUTO,
                    2500.00, ClaimStatus.SUBMITTED);
            system.addClaim(c1);
            assertEquals(1, system.claims.size());
            assertEquals(c1, system.claims.get(0));

            system.updateClaimStatus(1, ClaimStatus.UNDER_REVIEW);
            assertEquals(ClaimStatus.UNDER_REVIEW,
                    system.claims.get(0).status);

            system.addClaim(new Claim(2, 102, ClaimType.HEALTH,
                    8400.00, ClaimStatus.APPROVED));
            system.addClaim(new Claim(3, 103, ClaimType.PROPERTY,
                    15000.00, ClaimStatus.REJECTED));
            system.addClaim(new Claim(4, 104, ClaimType.AUTO,
                    950.00, ClaimStatus.APPROVED));
            system.addClaim(new Claim(5, 105, ClaimType.HEALTH,
                    3200.00, ClaimStatus.UNDER_REVIEW));
            system.addClaim(new Claim(6, 106, ClaimType.PROPERTY,
                    22000.00, ClaimStatus.APPROVED));
            system.addClaim(new Claim(7, 107, ClaimType.AUTO,
                    1800.00, ClaimStatus.REJECTED));
            system.addClaim(new Claim(8, 108, ClaimType.HEALTH,
                    6700.00, ClaimStatus.SUBMITTED));
            system.addClaim(new Claim(9, 109, ClaimType.AUTO,
                    4200.00, ClaimStatus.UNDER_REVIEW));

            Map<String, Object> stats = system.getClaimStatistics();
            assertEquals(9, stats.get("total_claims"));
            assertEquals(5, stats.get("total_resolved_claims"));
            assertEquals(55.56,
                    (double) stats.get("resolution_rate"), 0.1);
        }
    }

    public static void main(String[] args) {
        Result result = JUnitCore.runClasses(TestSuite.class);
        for (Failure failure : result.getFailures()) {
            System.out.println(failure.getTrace());
        }
        if (result.wasSuccessful()) {
            System.out.println("All tests passed successfully.");
        } else {
            System.err.println("Tests failed: "
                    + result.getFailureCount() + " test(s) failed.");
            System.exit(1);
        }
    }
}
